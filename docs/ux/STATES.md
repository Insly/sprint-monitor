## 1. Conventions

| Item | Value |
|---|---|
| Clock | Every "today", "now", countdown and switch is computed in **Europe/Tallinn**. Use `Intl.DateTimeFormat('en-GB', { timeZone: 'Europe/Tallinn', … })`. Do not use the device zone. When the device zone differs, times in the band carry the suffix ` (Tallinn time)`. |
| `CUTOFF_TIME` | `12:00`, read from `fix-cutoff.time` (not hard-coded). |
| `DEMO_TIME` / `LIVE_TIME` | `17:00` / `20:00` Tallinn (owner, v2.1). These are the usual start times, and they also switch on the evening state. Store them as optional `time` fields on `demo-update` / `live-update` (DESIGN §v2.1). |
| Deploy-time display | Wherever a deploy time is shown on the duty line or in the sprint view: `20:00 Tallinn · 19:00 Warsaw · 18:00 London` (via `Intl`, zones `Europe/Tallinn`, `Europe/Warsaw`, `Europe/London`). Elsewhere one zone, plus ` (Tallinn time)` when the device zone differs. |
| Phase on a deploy day | Cut-off Monday: `before` = now < 12:00, `after` = 12:00 ≤ now < 20:00, `evening` = now ≥ 20:00. Demo Tuesday: `day` = now < 17:00, `evening` = now ≥ 17:00. |
| Roles | `Everyone`, `IM/AM`, `Dev`, `QA`, `Lead`, `Analyst`. "Everyone" is the only name for the all-roles view. |
| Sprint context | Rail rows = `context(date).previous / current / next` (no fixed verbs). |
| Fixture times | When no time is given, the fixture time is **09:00 Tallinn**. |

## 2. Band states

| State | Treatment (both themes; tokens in DESIGN.md §10) | Who can get it |
|---|---|---|
| `urgent` | Full Insly Orange fill, charcoal text, large countdown | Cut-off Monday before 12:00 (all roles). Demo Tuesday before 17:00 (**Dev, QA only**) |
| `after` | Charcoal fill (`#1A1A1A`; dark `#0F0F0F` + 2 px orange outline), white text, orange state tag | Cut-off Monday 12:00–19:59 (all roles) |
| `evening` | Surface background + **8 px Green 1 left bar** + green `<tonight>` tag + order strip | Live Monday ≥ 20:00 (Everyone, IM/AM, Dev). Demo Tuesday ≥ 17:00 (Dev, QA) |
| `heads-up` | Light Orange wash (`#FFF1E5`; dark `#3A2410`) + 4 px orange **left** bar + "Tomorrow"/"Monday" tag | The working day before a Demo or a cut-off, only for that key day's **actors** (§3.3) |
| `event` | Plain surface, no colour bar. The headline carries the event | Any other day with an event or a minor heads-up |
| `quiet` | Plain surface, headline "No deadlines today" | Nothing for the role today or tomorrow |
| `weekend` | Gray Row fill (`#EDEDED`; dark `#2E2E2E`) | Sat, Sun |
| `preview` (overlay) | Charcoal bar above the band (dark: white bar). The band renders the previewed day's state at 09:00 Tallinn. No live countdown | Any `#date-` / `?date=` that is not today |
| `error` | Gray band: "Actions unavailable. Sprint dates below are still correct." | `rules.js` failed to load, or resolving the day threw (the error is logged; review 2.2) |
| `error` (range) | Gray band, headline and tab `No board before 2026-17` / `Sprint numbering for 2028 is not configured`; no rail, Coming up or duty line | A date before the anchor sprint, or one whose current or next sprint starts after the last `YEAR_STARTS` year (review 2.3) |

The four non-calm states (`urgent`, `after`, `evening`, `heads-up`) differ in **fill and bar position and colour and tag**, never in only one property.

## 3. Resolution algorithm (normative)

```
function band(date, now, role):                      # now = Tallinn HH:MM
  if isWeekend(date):                       return WEEKEND
  if isCutoffDay(date):                              # fix-cutoff today (B-1: phases, not "live-update today")
    if now < CUTOFF_TIME:                   return URGENT          # all roles
    if now < LIVE_TIME (20:00):             return AFTER           # all roles
    return role in {Everyone, IM/AM, Dev} ? EVENING : EVENT
  if isDemoDay(date):                                # demo-update today
    if role in {Dev, QA}: return now < DEMO_TIME (17:00) ? URGENT : EVENING
    return EVENT
  E = todayEvent(date, role)                         # §3.1
  H = headsUp(date)                                  # §3.2 (next working day)
  if H.key and role in actors(H):           return HEADS_UP
  if E or H:                                return EVENT
  return QUIET

function headline(date, now, role):
  key-day headlines: see §4. Otherwise:
  return join([E.text, H.text], ". ") or "No deadlines today"   # B-2: today's event leads
```

### 3.1 `todayEvent`: first match wins

| # | Condition | Applies to | Headline text |
|---|---|---|---|
| a | `code-freeze` opens today | all roles | `Code freeze starts today` |
| b | `sprint-planning` today | all roles | `{2026-22} sprint planning today` |
| c | `uatStart` today | all roles | `{2026-20} UAT opens: deadline {Mon 5 Oct} 12:00` |
| d | `sprint-start` today | all roles | `{2026-21} starts today` |
| e | a carry-over item for the role (§5) | role | IM/AM `Confirm the {2026-20} Live update to clients` · Dev `Create the Golive Release {2026-20} page` (after Live) or `Create the Release {2026-20} page` (after Demo) · Everyone `Morning after the {2026-20} Live update` |
| f | a timed meeting whose `who` includes the role | role | `{title} at {time}` |

### 3.2 `headsUp`: looks at the next working day

| Next working day has | Kind | Text |
|---|---|---|
| `demoStart` | **key** | `{2026-20} Demo update tomorrow` |
| `cutoff` | **key** | `Last working day before the {2026-20} cut-off` (the eve is always a Friday) |
| `planning` | minor | `{2026-22} sprint planning tomorrow` |
| `freezeStart` | minor | `Code freeze starts tomorrow` (the current sprint's; another sprint's freeze carries its label) |

### 3.3 Actors of a key heads-up (computed, not hard-coded)

Actors = Everyone plus every role in the `who` of rules dated on the key day or on its eve.
- Demo eve: `matrix-before-demo` (IM/AM), `demo-update` and `release-page` (Dev), `ready-for-demo` (QA) → **Everyone, IM/AM, Dev, QA**.
- Cut-off eve: `matrix-before-live`, `cutoff-reminder`, `cutoff-last-chase`, `tell-client-revert` (IM/AM), `fix-cutoff` (IM/AM, Dev), `live-update` (Dev) → **Everyone, IM/AM, Dev**.

Lead and Analyst (and QA before a cut-off) get the same headline in the calm `event` band.

## 5. Carry-over, first-day and last-day promotion

- **Carry-over (required in v2):** rules with `carryOver: 1` (`confirm-live-to-client`, `golive-page`, `release-page`) also appear on the **next working day**, under "From last night", worded as scheduled, not confirmed: "Last night's {2026-20} Live update was scheduled. Confirm to clients once the developers have."
- **Windows ≤ 7 days** (`code-freeze`, `regression-run`, `uat-window`, `ready-for-live`) are shown as full items on their **first day** ("Opens today") and their **last day** ("Last day"). In between they are one-line Running entries (Your day only). Windows of 8 days or more stay in "Every day this sprint". The sprint view lists every open window under "Every day this sprint" (it has no separate Running group).
- On the cut-off day, the last day of `uat-window` is **merged into the Fix cut-off row** as a sub-line ("UAT window closes at the same time"), not shown as its own row (M-3).

## 6. Sprint rail labels

`[phase]` is the segment highlighted on the 5-step bar `Plan · Build · Freeze · UAT · Live`.

| Condition for sprint `s` on `d` (time `t`) | Phase | Label |
|---|---|---|
| d < planning | Plan | `Refinement · planning {Thu 8 Oct}` |
| d = planning | Plan | `Sprint planning today · starts {Mon 12 Oct}` |
| planning < d < start | Plan | `Planned · starts {Mon 12 Oct}` |
| start ≤ d < freezeStart, weekday | Build | `Sprint day {n} of 10 · code freeze {Fri 9 Oct}` |
| same, weekend | Build | `Weekend · code freeze {Fri 9 Oct}` |
| d = freezeStart | Freeze | `Code freeze starts today · Demo update {Tue 13 Oct} evening` |
| freezeStart < d < demoStart | Freeze | `Code freeze · Demo update {Tue 13 Oct} evening` |
| d = demoStart, t < 17:00 | Freeze | `Code freeze · Demo update 17:00` |
| d = demoStart, t ≥ 17:00 | Freeze | `Demo update tonight` |
| d = uatStart | UAT | `UAT opens today · fix cut-off {Mon 5 Oct} 12:00` |
| uatStart < d < cutoff | UAT | `UAT on Demo · fix cut-off {Mon 5 Oct} 12:00` |
| d = cutoff, t < 12:00 | Live | `Fix cut-off 12:00 today · Live update tonight` |
| d = cutoff, 12:00 ≤ t < 20:00 | Live | `Cut-off passed · Live update tonight 20:00` |
| d = cutoff, t ≥ 20:00 | Live | `Live update tonight` |
| d > live | Live | `Live update was {Mon 5 Oct}` |

Freeze copy everywhere: the freeze lasts "until the Demo update {Tue 13 Oct} (evening)". Where a reopening needs mentioning, write "Beta reopens {Wed 14 Oct}". Never use "until Wed" as the freeze end.

## 10. Sprint view states (v2.1)

Route: `#sprint-{label}`, e.g. `#sprint-2026-21`. Combined with a preview date: `#date-2026-10-01~sprint-2026-21`. Only `[A-Za-z0-9._~-]` is accepted; anything else is ignored. The view is a full view, not an overlay (DESIGN.md §v2.1).

| State | Condition | Rendering |
|---|---|---|
| `current` | `n = context(today).current.n` | Status line `Sprint day 4 of 10 · code freeze Fri 9 Oct`. The "Today" marker sits between the passed and the coming milestones |
| `releasing` | `n = previous` | e.g. `UAT on Demo · fix cut-off Mon 5 Oct 12:00` |
| `upcoming` | `n = next` or later | e.g. `Refinement · planning Thu 8 Oct`. The marker sits before the first milestone. Projected sprints get the `projected` tag |
| `past` | `today > live` | `Live update was Mon 5 Oct`. All milestones show `Passed` |
| `unknown` | Label does not parse, `n < ANCHOR.number`, or the sprint starts after the last `YEAR_STARTS` year (`2027-28`) | h1 `No sprint 2026-99`, with links to Today and to the current sprint |

Milestone status uses only dates and the Tallinn clock: `Passed` (date before today, or a timed milestone today whose time has passed), `Today`, `Coming · in N working days`. **Never "done".**

## 11. Holiday notices (v2.1)

Data: `public/holidays.js` (DESIGN.md §v2.1).
